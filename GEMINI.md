# Инструкции проекта: Myna Quick Note

Данный файл содержит командные соглашения, правила разработки и архитектурные требования для проекта **Myna Quick Note** (GNOME Extension).

## 1. Структура и расположение файлов
- **Планы разработки:** Все планы и документы в режиме планирования должны сохраняться исключительно в директории `plans/` в корне проекта.
- **Документация тестирования (QA):**
  - `qa/checklists/` — мастер-чек-листы (единый источник актуальных тестовых сценариев и проверок функционала).
  - `qa/reports/` — итеративные отчеты-планы тестирования. 
    - **Рабочий процесс QA:** Перед тестированием новой итерации или фичи агент генерирует в `qa/reports/` отчет-план на основе мастер-чек-листа. Разработчик/тестировщик выполняет проверки на реальном окружении (GNOME Shell), проставляет статусы (`[x]`) и дополняет файл реальными логами (`journalctl` и др.), после чего фиксирует изменения в репозитории.

## 2. Стандарты разработки и Git
- **Язык:** Вся документация, комментарии и сообщения коммитов оформляются на **русском языке**.
- **Conventional Commits:** Используйте стандартные префиксы (`feat:`, `fix:`, `docs:`, `refactor:`, `test:`).
- **Соавторство:** Все коммиты должны содержать подпись соавтора:
  `Co-Authored-By: Gemini CLI <gemini-cli@users.noreply.github.com>`
- **Ветвление и Pull Requests:** Разработка ведется в короткоживущих ветках (`feat/`, `fix/`, `docs/`). Каждая завершенная итерация в ветке оформляется созданием Pull Request на GitHub (с помощью `gh pr create`). Слияние (merge) пулл-реквестов производится на GitHub, а локально выполняется получение обновлений (`git pull`).
